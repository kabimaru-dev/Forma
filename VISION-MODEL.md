# Forma 5.5 — отдельная модель для фотографий

В `config/modes.yaml` есть **единственный** параметр для vision-модели:

```yaml
vision_model: ""
```

Если ты обновляешь Forma архивом «только код», то при первом обращении к настройкам режимов Forma безопасно добавит этот параметр в твой существующий `config/modes.yaml` (один раз, с резервной копией `config/modes.before-vision.bak`). Остальные назначения моделей не меняются. Если файл доступен только для чтения, добавь строку вручную.

Впишите точное имя локальной мультимодальной модели, которая уже установлена в Ollama, например `vision_model: "имя:тег"`. Не нужно назначать vision-модель каждому уровню: она одна на весь сайт.

При отправке одного или нескольких изображений Forma сначала вызывает указанную Ollama-модель с полем `images`, получает текстовое описание, а затем передаёт его основной модели. Оригинальные байты фотографии не записываются в SQLite; описание сохраняется как часть сообщения, так что история читаема после перезагрузки. Мост не гарантирует точного распознавания всего содержимого фотографий.

Загрузка нескольких файлов поддерживает текстовые документы и JPEG, PNG, WEBP, GIF. Число файлов не ограничено счётчиком; действует практическое ограничение 100 000 символов на текст, 8 МБ на один снимок и 24 МБ на совокупность снимков в одном сообщении. GIF обрабатывается по возможностям установленной vision-модели.

Если vision_model не заполнена, отправка фотографий выдаст понятную ошибку, но обычный чат останется рабочим. Конфигурация моделей остаётся серверной; API не раскрывает имя vision_model.
