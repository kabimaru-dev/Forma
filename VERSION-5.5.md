# Forma v5.5 — исправление n_gen

Версия остаётся v5.5. Счётчик использует только **реальный `eval_count`** из завершающего чанка Ollama `/api/chat`, эквивалент `n_gen` в логах llama.cpp. `prompt_eval_count` (входные токены) НЕ используется как `n_gen`.

- `Токенов: N / лимит` показывает сумму сгенерированных моделью токенов ответов данной истории, для которых Forma получила точный `eval_count`. **Это счётчик генерации, а не занятость контекста.**
- Каждый завершённый ответ записывается по его идентификатору в отдельный файл `.forma-n-gen.json` рядом с активной БД. Это позволяет сохранять точные значения при перезапуске и переключении историй, не меняя саму БД.
- Для старых ответов, созданных до этого исправления, оригинальный `n_gen` нельзя задним числом получить из Ollama. Если в истории есть такие ответы, вместо придуманного точного итога показывается `—`; в подсказке видно, сколько токенов удалось подтвердить и для скольких ответов статистики нет.
- При повторной генерации текущий подсчёт использует только ответы, оставшиеся в истории, и не включает удалённый при retry ответ.
- Запрос GET `/api/chats/:id/tokens` больше не запускает модель и не вызывает лишнюю однократную генерацию ради `prompt_eval_count`.
- Номер версии, конфигурация режимов и визуальное оформление сохранены. Данные `data.db`, `data.db-wal`, `data.db-shm`, а также исходный `config/modes.yaml` не изменялись.

**Предупреждение:** если при установке уже есть `.forma-n-gen.json`, сохраните его вместе с рабочей базой. Не загружайте этот файл в публичный GitHub.

## Автоматическая подгрузка контекстного окна (обновление v5.5)

В разделе «Настройки → Ответы» добавлены два ползунка:

- **Загружать модель по достижении N токенов** — шаг 0–32768, с делениями в 1024 токена. Значение 0 выключает автоматическое расширение и использует выбранный ручной контекст. Значение 8192 начинает с окна 8192 и по мере использования включает 16384, 24576, 32768 и так далее до 262144.
- **Заранее загружать модель, если до лимита осталось N токенов** — запас 0–16384, с делениями в 1024 токена. Значение 0 — только обычные ступени. Когда запас достигается, выбирается окно до двойного размера текущего: 32768 → 65536 и 49152 → 98304; максимум — 262144. Для окна меньше удвоенного запаса упреждение ограничивается половиной текущего окна.

**Важно:** переполнение контекста определяется фактическими `prompt_eval_count` + `eval_count` из *завершённого* ответа Ollama `/api/chat`. Эти поля служат **только для переключения окна** и не влияют на вывод счётчика `n_gen`, который по-прежнему берётся строго из `eval_count`. Смена окна происходит **между ответами**, не посреди генерации. Для старых историй без записанной статистики реальную заполненность восстановить нельзя. Очень длинное следующее сообщение тоже способно превысить окно до нового измерения; упреждение уменьшает риск, но не даёт абсолютной гарантии.

Выполняется реальная предварительная загрузка через пустой запрос к Ollama `/api/chat` с `options.num_ctx` и `keep_alive: "10m"`; каждый реальный запрос генерации также указывает активное значение `num_ctx`. Запуск подгрузки из завершённого ответа откладывается, если другая генерация ещё активна (следующая отправка инициирует нужную загрузку). Состояние окон хранится **в отдельном файле `.forma-context-windows.json` рядом с data.db**, исключённом из Git. База данных, её схема, `config/modes.yaml` и сохранённые старые истории не менялись при сборке архива. Настройки сохраняются в уже существующем JSON-поле пользовательских предпочтений, без миграций.

Максимальная ёмкость 256K **возможна только при поддержке её выбранной моделью и наличии памяти**. Предзагрузка не гарантирует, что Ollama сможет выделить ресурсы; при ошибке загрузки Forma сообщит об ошибке, не подменяя результат меньшим окном. При переключении на другую модель её состояние окна начинается заново. Для ручного режима остались варианты до 256K.


## Исправления 5.5: редактор и постоянные настройки

- При отправке текст очищается из поля ввода сразу после проверки (при раннем отказе сервера без сохранения сообщения восстанавливается).
- Редактор любого пользовательского сообщения и ответа модели использует отдельное текстовое поле; его текст не появляется в поле отправки.
- PATCH `/api/chats/:id/messages/:messageId` сохраняет редакции прямо в JSON-поле `chats.messages` существующей SQLite БД. У сообщения сохраняются `revisions` и `revisionIndex`: можно переключать предыдущую/следующую редакцию и переходить между сообщениями из редактора.
- Более поздние ответы модели не перегенерируются и не удаляются после изменения раннего сообщения; при следующих отправках модель увидит текущую редакцию истории.
- Глобальные параметры окна для аккаунта: по умолчанию шаг 16384 токенов, упреждение 8192 токенов. Один раз обновляется сохранённая старая пара значений 0/0; затем собственные настройки, в том числе 0/0, не перезаписываются. Ползунки автоматически сохраняют изменения в SQLite-предпочтениях аккаунта.
- Запрос отправки сразу открывает NDJSON-поток с heartbeat до начала выдачи Ollama; отдельная ненужная загрузка модели перед **каждым** сообщением удалена. Существующая подготовка следующего контекста после завершения ответа сохраняется.
- Установленная SQLite-база в полном архиве сохранена без миграции структуры; необходимые изменения данных происходят только при использовании сайта. Для обновления существующей установки используйте архив без базы и без `config/modes.yaml`.
